## 行、一打席、一つの状態遷移の違い

原本の `pa=1` は14指標のちょうど一つと一致することを検査しました。NP 1,884行を非プレーとして分離し、**実プレー568,664行、完了打席549,479件**を抽出。盗塁・暴投・捕逸・牽制・走塁死・ボーク等は実プレーとして残し、打席結果を作っていません。原本の非対象試合分10,567行は今回の範囲外です。

「観測打席の窓」は、直前の打席完了／半イニング開始後の最初の実プレーから、次の打席完了または第3アウトまでです。例えば `盗塁→単打` を一つの窓へまとめることで、単打の終了行の走者状態を打席の開始状態と取り違えません。窓は550,794件、複数の実プレーを含むものは17,410件でした。最初の投球そのものを復元した単位ではありません。

打席完了前の走者アウト等による終了窓は1,315件。このうち16件は第3アウト前の試合終了で打ち切られたため、結果・遷移モデルの訓練対象から除外しました。残る1,299件は `runner_only_end` とし、打順を進めません。途中で打者または投手が変わった窓は27件あり、開始時点で観測したIDを入力に保持します。選手別の観測成績CSVは終了行のIDで集計するため、両者の定義を区別しています。

サヨナラ等で第3アウト前に終了した最終窓は **626件（サヨナラ622、短縮・途中終了4）**。原本の終了状態には走者が消去される例があるため、通常の進塁として学習しません。完了打席の区分は保存し、これらの窓は遷移の推定・評価から外します。残り得点の集計も未完了の半イニングを除外します。非打ち切り窓に保存則の未解決例外は0件でした。

敬遠1,539件は四球の内数、振り逃げでの出塁180件は三振の内数です。犠打・犠飛、野選、失策、複数アウトを「通常のアウト1つ」に置き換えず、元の分類と遷移を保持します。延長1,760半イニングの最初の観測状態はいずれも無死二塁。自動走者の配置をプレーとして数えず、通常回と延長の遷移を区別しました。配置される走者の資格までは再検証していません。

## 確率推定と信頼性

窓結果の15クラスについてリーグ平均に各0.5の事前度数を加え、左右別はリーグへ100件相当、条件別は左右別へ25件相当、打者・投手はそれぞれリーグへ500件相当で縮小。選択された予測は **条件成分50%＋打者25%＋投手25%** です。成立しない犠打・犠飛や走者のみの終了を開始状態に応じて除き、正規化します。完了打席を条件とするときは走者のみの終了を除いて14クラスへ再正規化します。

4,773条件群の観測件数中央値は18件で、2,901群は30件未満、1,675群は10件未満でした。無平滑の細分化は不安定です。例えば観測5件の条件は直接の条件成分の重みが `5/(5+25)`、さらに全体混合の50%となり、一部の偶然の結果が全体を支配しません。未知の条件は左右別→リーグ、未知の選手はリーグへ戻ります。2025年には未観測の打者IDを使う窓15,515件、投手ID20,472件、未観測の条件171件があり、この経路を使いました。

遷移は `P(次状態, 得点 | 開始状態, 窓結果, 通常/延長)` を同時分布で推定。同じ状態・結果の両区分を共有する事前分布（100件相当）へ縮小し、保存則を満たす候補に計0.5件の一様事前度数を加えています。保存則は全公式ルールを網羅しません。原本にない個別プレーや計測値を作ったわけではなく、未観測候補の確率はモデル上の仮定です。

`conditional_posterior_sd` は親分布を固定した近似です。選手内相関・同じ半イニングでの反復・年度間変化の不確実性を含む保証区間ではありません。得点期待値も記述統計で、因果的な走塁能力や真の選手能力の推定ではありません。

## 年度分割と未来情報の防止

1. 2023年を訓練、2024年を検証。条件平滑化4候補×選手比率3候補を対数損失で比較。
2. 選ばれた打席モデルを使い、遷移の平滑化3候補を2024年で比較。
3. **設定を固定して2023〜2024年で再推定、2025年で評価**。

訓練は366,553完了打席、走者のみの終了を含め367,398窓。評価は182,926完了打席、183,380窓。遷移評価は打ち切りを除く183,160窓です。2025年の成績・終了状態・得点・打席結果・終了時のカウント・投球列を入力に使いません。終了した試合の得点差も使わず、窓の開始時点で打撃側から見た点差を使用します。

平滑化25と遷移100は今回の候補範囲の端でした。2025年の結果を受けて候補を広げ直していません。テストでは2025年のラベルを変更しても `model.json`・`kernels.json`・2024年の選択結果が変わらないことを確認しています。

このため、**状態と得点だけを進めたい用途では状態別ベースラインを優先**し、打席結果を付けるモデルは検証用として区別します。APIには両方を残しています。精度の劣る結果を隠して「高度化で改善」とは結論付けていません。通常回と延長別の全結果は [evaluation_metrics.csv](../../data_sources/stage6/evaluation_metrics.csv)、設定・区間推定・定義は [evaluation.json](../../data_sources/stage6/evaluation.json) です。

## データ不足と未実装の要素

- 球速・回転・変化量・実際のコース・打球角度・打球軌道は推定していません。小規模な研究値で公式戦の測定値を埋めていません。
- 対象は2023〜2025年のMLBレギュラーシーズン。DH・用具・守備・起用・戦術・現行ルールを含み、NPBや架空リーグの代表標本ではありません。
- 四球には敬遠、犠打等には戦術選択を含みます。投手・打者成分は観測された成績への縮小で、相手や球場を完全調整した潜在能力ではありません。
- 一球ごとの意思決定、疲労、球種、守備位置、個々の走者の速さ、捕手能力、球場や気象の因果効果はモデル化していません。
- 状態は塁の占有とアウト数だけです。誰が進んだか・誰が得点したか、投手の失点責任、打順別の個人成績をこの遷移だけから確定できません。
- サヨナラでの打球の公式記録・進塁の打ち切り、アピール、走者の追い越し、複雑な第3アウト、継投制限、正式な勝敗投手などの完全な公式ルール処理は別途必要です。
- 完了半イニングだけの残り得点集計や、打ち切りを除く遷移には選択の影響があります。独立な正確性検証やリーグ間補正が済んだ値ではありません。

## 第7段階でCatBoostを使うか

**本格導入は見送ります。第7段階は校正と、打席結果から状態・得点へつなぐ分布の整合を優先します。** 現状でも打席結果は改善しましたが、校正と同時遷移が単純な基準を上回っていません。分類器だけを複雑にしても、ゲーム全体の得点や進塁が改善するとは判断できません。

その後の小規模な比較候補としてCatBoostは妥当です。左右・状態・回・点差・訓練時点の選手IDを扱えます。今回の縮小表を基準に、同じ期間分割・推論時に利用可能な特徴のみ・同じゲーム単位の区間推定で比較し、校正と遷移の整合まで改善した場合に採用します。2025年を反復調整に使うなら、最終評価には別の未使用期間が必要です。

## 架空シミュレーターへの接続

[利用手順のAPI例](../../data_sources/stage6/README.md#api) から、`predict_pa` で打席結果、`predict_next_state_runs` で条件モデルの同時分布、`predict_state_baseline` で状態別基準を呼べます。`sample_step` は窓結果を抽選してから次状態・得点の組を抽選し、互いに矛盾する独立抽選を避けます。

打席完了時だけ打順を進め、半イニング終了で攻守交代。延長開始の走者配置、勝敗・サヨナラ判定、個人IDと記録責任はルール層で処理します。既存の一球モデルへそのまま差し替える契約ではありません。まず別モードの粗い状態シミュレーターで基準分布を確認し、人物を保持する進塁の契約を定めてから既存エンジンへ接続する形が適切です。

架空選手に実在IDを割り当てず、初期段階は選手IDを指定せずリーグ・条件の基礎分布を使えます。既存アプリの両打ち表現 `S` は、このAPIで使用するRetrosheet区分 `B` と対応付ける必要があります。架空能力への補正や個人成績の較正は今回実施していません。
