# 台帳の調査方法と読み方

[台帳トップ](README.md) / [重点候補と発見事項](findings.md)

## 第1段階の成果物

取得先の候補、説明資料、収録期間の主張、入口への接続、利用条件の確認状況を記録します。試合レコードを抽出したサンプルセットの作成、全年度の取得、学習、シミュレーターの確率変更は第2段階以降です。

今回取得したのは公開ページ・説明文書・ライセンス・配布一覧などの調査資料です。SportsDataverseについては、データ本体を取得せず収録manifestのindexだけを読みました。調査中のホームページには成績等の表示が含まれる場合がありますが、それを選手・試合レコードとしてDB化していません。

## 調査範囲

12分類で候補を整理しました。MLB・NPB、ファーム・マイナー、大学・高校・社会人・独立リーグ、女子・代表戦、アジア・米州・欧州・豪州の入口を含みます。天候、球場、動作・疲労研究、契約、制度、文献・公開データの探索先も含みます。

公式サイト・公的機関・原著者の配布を優先し、既存OSSの説明資料、配布元のREADME、ライセンス、データシート、列定義、収録一覧を照合しました。GitHubの公開リポジトリ検索も使用しました。検索語・日時・検索結果は [discovery_queries.json](../../data_sources/discovery_queries.json) にあります。NPBという文字を含むベイズ統計などの無関係な検索結果は候補に採用していません。

これは主要な情報源の系統を横断した初版です。インターネット上の全サイト・全地域リーグ・個々の全論文を調査し尽くしたという意味ではありません。発見したリンクから次の候補を追加し、廃止・更新・利用条件を継続確認します。

## 件数の数え方

- 1件はデータセット、取得入口、参考資料、または研究・データ探索の入口です。
- 同じBaseball Savant内の異なる計測資料などは別項目にし、同一の `provider_group` で識別します。提供元グループ数は独立企業数ではありません。
- `dataset`、`portal`、`research_index`、`reference` を区別します。論文検索サイトを「野球の実データを取得済み」と数えません。
- 補助ツールは別表です。同じLahmanデータを扱う複数のクライアント・配布形式を独立した観測データとして扱いません。

## 状態は分けて判断する

| 項目 | 意味 |
|---|---|
| 資料確認済み | 入口や内容について具体的な説明資料を読んだ。根拠URLと確認メモを記載 |
| 一次資料未確認 | 候補として登録したが、内容を一次資料で十分に確認できていない |
| reachable / HTTP 200 | そのURLへの接続を確認。実データ・APIの動作やページ本文の正しさまで保証しない |
| http_error | HTTPエラー。404、403、429等のコードを保存。サイトの永久閉鎖とは判断しない |
| proxy_blocked | この環境のプロキシ経由で接続を拒否された。提供元自体の障害や非公開とは判断しない |
| connection_error | 接続・TLS・時間切れ等。例外の種類のみ保存し、資格情報を含み得る例外全文は保存しない |
| rate_limited / skipped_after_rate_limit | 429または同じホストへの後続要求を停止した状態 |
| documented / mixed / restricted / needs_review | 利用条件の確認段階。説明資料を読めたことと利用許可は別 |
| not_collected_stage1 | 統計レコードのサンプル取得・品質検査はまだ実施していない |

入口の資料を確認できても、収録年、料金、欠損、再配布条件まで全項目が確定したとは扱いません。項目ごとの不確実性はcoverage・rights・limitations・next_actionに残します。`unknown` と未確認を0や「無料・自由」と置き換えません。

優先度A/B/Cは**次の調査の順序**です。Aでも許諾・仕様の確認が残るものがあります。自動取得を承認する印ではありません。公開されている、GitHub上にある、クライアントがMITという事情だけで、元データの学習・再配布・商用利用が許されるとは扱いません。

## 接続・取得量の扱い

`scripts/catalog.py check-links` はポータル・文書のURLだけを確認します。原則GETで最大128KiBと打ち切り判定用1バイトを読み、PDFはHEADでメタデータだけ確認します。ホストごとの要求を直列化して間隔を設け、429の後はそのホストへの残りの要求を止めます。既存の記録は再利用し、再確認には `--refresh` または `--retry-status` を明示します。

初期の接続制限には必要なドメインだけの環境設定追加を保存し、接続結果を再確認しました。設定の保存、実際の接続成功、環境のPublishは別です。後続タスクで同じ接続ができるかは、その実行環境で再確認します。サイト側403・認証・有料範囲の回避は行いません。

説明文書を読むために別途取得したHTML・README等の原文は一時ディレクトリに置き、リポジトリには原文の大量コピーを含めません。根拠URL、確認メモ、確認した文書のハッシュを残します。接続記録の `observed_body_sha256` は最大128KiBの受信部分に対する値で、野球データ本体の完全性検証用SHA256ではありません。

文字コード、メタタグによる画面遷移、JavaScript描画にも注意が必要です。入口200でも目次だけ・遷移案内だけという例がありました。URLを修正した履歴は [url_corrections.json](../../data_sources/url_corrections.json) に残します。

## 保存形式と更新

- [catalog.json](../../data_sources/catalog.json): 編集元。出典・期間・形式・条件・注意点・次の調査を保持。
- [sources.csv](../../data_sources/sources.csv): Excel向けUTF-8 BOM付きの一覧。
- [link_checks.json](../../data_sources/link_checks.json): URLごとの確認時刻・HTTP結果・タイトル等。
- [summary.json](../../data_sources/summary.json): 件数・分類・状態の集計。
- `data_sources/catalog.sqlite3`: buildで生成するローカル台帳DB。Git管理から除外。sourcesとlink_checksをSQLで検索可能。
- `docs/data-sources/`: 分類別の閲覧ページ。JSONから再生成。

```bash
python scripts/catalog.py validate
python scripts/catalog.py build
# 新しく追加したURLだけ確認
python scripts/catalog.py check-links
# 接続制限が解消したときの再確認例
python scripts/catalog.py check-links --retry-status proxy_blocked
python scripts/catalog.py build
```

buildは台帳専用の派生DBを作り直します。編集元はJSONです。試合用の `data/lab.sqlite3`、ゲームのモデルや成績、依存関係のロックには変更を加えません。

## 次の段階で確認すること

許諾と取得方法を確認した候補から少量の試合・年度・観測所を選びます。空応答・取得失敗・真にデータなしを区別し、件数・主キー・欠損・単位・時点・訂正・別資料との一致を検査します。氏名だけで人物を結合せず、提供元IDの対応を保持します。MLBとNPB、年度ごとのルール・測定方法の違いも残します。

第1段階の台帳の完成は、第2段階のサンプル取得・品質検査の完了を意味しません。
