[台帳トップ](README.md) / [調査結果](findings.md)

調査日: 2026-10-21。作業環境はLinux / Python 3.12。以下は台帳と調査資料の検証結果です。実データの取得・統計検査・モデル学習の成功を示すものではありません。

## 実行したコマンド

リポジトリ直下で実行しました。

```bash
.venv/bin/python scripts/catalog.py validate
.venv/bin/python scripts/catalog.py check-links
.venv/bin/python scripts/catalog.py check-links --retry-status proxy_blocked
.venv/bin/python scripts/catalog.py check-links --retry-url https://www.big6.gr.jp/
.venv/bin/python scripts/catalog.py build
```

ネットワーク設定変更、URL修正、文字コード診断などの後に、影響したURLだけを再確認しました。チェックは完了し、最終の各URLの観測はlink_checks.jsonに保存しています。全URLを何度も連打する検査は行っていません。

## 整合性と再生成の確認

Python標準ライブラリで次の検証を実行し、すべて成功しました。

- JSONの128件が一意のID・入口URLを持ち、12分類、84グループ、13ツールの集計と一致。
- 資料確認済みの項目に根拠URLがあり、全項目に次の確認事項と注意点がある。
- 必要な全201 URLに接続結果がある。未検査URLを成功扱いしていない。
- Excel向けCSVとJSONのID集合・行数が一致。
- SQLiteのsources 128件とlink_checks 201件が一致し、`PRAGMA integrity_check` が `ok`。
- 新規ドキュメントとREADMEのリポジトリ内リンクが実在する。
- 東京六大学の文字コードをCP932として扱い、日本語タイトルを正しく取得。
- buildの再実行でCSV・Markdown・集計JSONが同一となり、SQLiteの行内容も一致。
- 4件の入口URL修正について、以前のHTTP結果と修正理由を保存。

SQLiteは台帳専用の派生ファイルでGit管理から除外しています。既存の野球アプリのゲームDB、試合モデル・ルール・成績、依存関係のロックは変更していません。アプリのpytestは今回の変更に対して再実行していません。
