# 第8段階のルール・成績・停止の契約

## 再利用と追加

第7段階の `CalibratedModel` を確率推論にそのまま利用し、`Frame / RunnerToken / Move / Plan / Transition` を共有します。標準のルールでは従来の `apply_plan` を呼びます。`advance_half`、交代処理、`Journal` のハッシュ連鎖・状態の指紋・旧操作の実行器も再利用します。旧ソースと旧ジャーナルの解釈は変更していません。

第8段階の `Play` は `Plan` に打数・塁打・打点対象者・犠打犠飛・責任投手の情報を付けます。`apply_play` はこれを検証し、`Applied` を返します。`GameJournal` は `Journal` の拡張版で、追加操作とルール版 `fullgame-rules-1` を識別します。旧 `replay` に新ログを渡さず、新しい再生器を使います。

## 原本を使う追加経路

得点者・進塁後ID・残塁からの復元方法を保持し、原本の `ab / rbi_b / rbi1..3 / sh / sf / gdp` 等を合わせます。原本が打数・安打・打点を記録している場合、その記録を経路とともに保持します。単なる24状態表から個人成績を作りません。

打者が安打の塁を確保した後にアウトになる経路、打者が生きた犠打犠飛、一塁付与と追加進塁を、原本で確認した経路として適用できます。同一プレーの第3アウトと得点は、原本で数えられている得点者集合を `source_counted` として保持します。これは**原本の記録判定を使う機能**で、正確な得点時刻・アウト順・フォース／アピールを新しく復元したものではありません。

明示的な外部プレーで得点を伴う第3アウトを指定する場合は、得点が先であるタグアウト等の裁定が必要です。不明な順序、フォースや一塁到達前の第3アウトに得点を加える入力は拒否します。架空の時刻は補いません。

通常の次状態が観測されないサヨナラ・短縮終了、窓途中の打者投手変更、参加者の変更を現在の復元器で追えない場合は、通常回の学習経路から除外します。原本に情報がないという意味ではありません。2025年の経路は学習に加えません。

二死から唯一のフォースアウトが `5(2)/FO...` 等と明記されているのに一部の残塁IDが欠ける記録は、アウトになった開始塁の選手をプレー記述で特定し、残る参加者を残塁として復元します。得点0・アウト増分1等の条件を要求し、最終塁は推測しません。修復した経路には `recovery_note` を残します。野選の打者が一塁到達前にアウトになった記録について、野選という名称だけで一塁に到達したと仮定しません。

## 明示的な仮定

APIの標準は原本由来の経路だけです。`allow_assumptions=True` の場合だけ、原本件数に10件相当の固定進塁を加えます。単打1塁分・二塁打2塁分などの旧仮定を引き継ぎます。

追加した野選の仮定は、一塁に走者がいれば一塁走者、それ以外は最も先の走者をアウトにし、打者を一塁へ置く限定経路です。二死三塁も処理できますが、**新しく実測できた経路とは扱いません**。未観測の打席未完了終了では、適当にアウト選手を選ぶ仮定を置いていません。

各プレーの `source` は `empirical / assumption / explicit_event`。全ての経路選択は一度だけです。結果や経路が非対応なら、その抽選を捨てて成功するまで引き直す処理はありません。

## ルールと記録

- 9回制、打順、攻守、3アウト終了、裏9回の省略、延長上限・引き分け・二塁自動走者の設定に対応。
- 非本塁打サヨナラは勝利点まで。本塁打は全員得点。非本塁打の安打価値は勝利点に必要な塁数まで短縮（OBR 9.06(f)）。一般化した経路で、サヨナラ得点とアウトの前後が確定しない場合は停止。
- 通常の捕球による犠飛でアウトが打者1人だけなら、捕球アウトがタッグアップ後の得点より先と判定してサヨナラを処理。落球後の追加アウトなど、この条件で前後関係を証明できないものは停止を保持。
- 打席未完了の走塁死ではPA・ABを加えず、打順を維持。自動走者配置もPA・安打とはしない。
- PA、AB、安打・長打、四死球、三振、得点、原本に沿う打点、投手のアウト数・被安打等を集計。投球回は整数アウト数が本体で、`ip_display` の「6.1」は6回1/3の表示。
- 代打・代走・投手交代はカウント開始前の基本処理。再出場を拒否し、代走でも責任投手を保持。窓と別の一球・盗塁抽選を混ぜない。
- 単純な野選で一塁走者がアウトとなり打者が置き換わる場合、元の走者の失点責任を継承（OBR 9.16(g)）。複雑な置換で投手責任が確定できない場合、その投手の失点はnullとし、勝敗投手も要確認にする。
- 勝敗投手は取り戻されなかったリードと決勝走者の責任投手から判定。先発5回条件、救援1人の限定条件を処理。複数救援の有効性に記録員の裁量が必要なら勝利投手を決めず要確認（OBR 9.17）。

原本由来の経路を新しい試合へ当てはめることも統計モデル上の推定です。個々の選手の能力・疲労・球場・守備・戦術を実測に基づき再現したとは称しません。本塁打は基本的に全員得点の経路で、フェンス越え／ランニング本塁打の全例外は未対応です。

## 完成していない公式記録・ルール

全自責点の再構成、セーブ・ホールド、複数救援の裁量判定、盗塁等の全公式個人成績、登録資格・最低対戦打者、二刀流・守備位置変更、途中カウントの交代責任、自動走者の投手打順例外、アピール・第4アウト、詳細な進塁タッチ順、天候による短縮・再開、ランニング本塁打のサヨナラ例外は未完成です。

`full_official_record=false` を維持します。未知の自責点・セーブ・ホールドを0にしません。打点や失点責任が不明な選手は該当項目がnullです。内部の責任分配は整合性検査にだけ使い、確定した公式値と称しません。

## 未対応経路の分類

1. **原本に情報あり、実装で対応**：伸塁アウト・安全な犠打等の原本の結果と得点・打点を使う追加経路。
2. **解析不足**：途中の交代、NP・ラインアップとの未結合、参加者差分不一致、通常終了とサヨナラ終了の意味の切り分け。
3. **現在の情報だけでは未確定**：同一プレー内の時刻・順序、原本の最終状態だけから公式記録を新規判定する場合。より詳しいプレー記述の解析で解消する余地は別に扱う。
4. **追加ルールが必要**：複雑なサヨナラ、フォース・アピール、公式自責点、裁量を伴う勝利投手等。
5. **モデルの表現・支持不足**：正の確率があっても2023〜2024年に対応する通常回の経路がない結果。2025年だけの経路を流用して解消したとはしない。

分類は重複し得ます。個々の元8ケースと原本参照は `stage7_failure_reproduction.json`、今回の全停止は `failures.json`。停止には試合ID・選手ID・前状態・シード・モデル版・ルール版・乱数状態を保存します。
