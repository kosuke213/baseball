# 第8段階への接続契約

## 再利用するもの

- `baseball_simulation_lab.calibrated.api.CalibratedModel`：`load`、`predict_pa`、`predict_step`、`support_report`、`resolve_outcome`、`sample`。
- `rules.Frame` / `RunnerToken` / `Move` / `Plan` / `Transition`：不変のゲーム状態と個人の移動。
- `rules.apply_plan` / `advance_half` / `runner_event` / `count_event` / `substitute` / `change_pitcher`：確率から独立した状態処理。
- `replay.Journal` / `replay`：モデル版・ルール版・初期状態・シード・実際の決定を保存し、新モデルで再抽選せずに再生。
- `base_model.json` / `calibration.json` / `identity_model.json` / `kernels.json` / `manifest.json`：固定モデルと指紋。

## 呼び出しの順序

1. 2球団の各9人の打順・先発投手を `Frame` に渡す。架空IDは全球団で一意にする。既存 `domain.Runner` の `player_id`・責任投手は `RunnerToken` へ明示的に移す。
2. `predict_pa` は完了打席の14分類、`predict_step` は打席未完了の走者アウト終了も含む15分類。窓全体の抽選と、途中の走者イベントの個別抽選を重複して実行しない。
3. 自動生成なら `sample(state, random.Random(seed))`。外部の打席結果を使うなら `resolve_outcome`。一球モデルから途中まで進めた状態に窓全体のモデルを重ねると盗塁等を二重計上するため、契約を分ける。
4. `WindowResult.transitions` は途中の実プレーを含む。`scored` は得点者と責任投手、`out_ids` はアウト者、各遷移の `stranded_ids` は残塁者、`halted_ids` はサヨナラで打ち切った選手。
5. ルール層は打席完了時だけ打順を進める。3アウトでは追加の攻撃を拒否。明示的に `advance_half` を呼ぶ。延長開始の走者配置はプレーや打席として記録しない。
6. `Journal.record_window` で実際の経路を保存。既存のログは上書きせず、`replay` は確率モデルを呼ばない。ルール版が不明なログは現在のルールで黙って再計算しない。

## 既存エンジンとの互換性

既存の `PitchOutcomeModel` は一球単位、第7段階のモデルは観測打席の窓単位です。同じインターフェースへ差し替える変更はしていません。`Game.apply_pitch` に新APIの1窓を1球として渡すことは禁止します。

第8段階では別モードの実験エンジンを作り、旧モードと旧公式記録は保持してください。個々のイベントのAPI版・モデルSHA・ルール版を保存し、過去の記録が新モデルで書き換わらない形で接続します。実在成績と架空の潜在能力の関係付けは、別の較正・検証課題です。

## 統合を止めるべき条件

- `UnsupportedRule` が出たら、都合のよい結果が出るまで引き直さない。実験を停止し、入力状態とシード・モデル版を保存する。
- `support_report` で未観測の結果確率が残る状態に、全試合が必ず完走することを保証しない。
- 仮定を許可する場合は `allow_assumptions=True` を明示し、記録上も実測由来とは区別する。標準の経験的経路限定モードと、今回の混合モードの評価を混同しない。
- 得点だけの24状態表から誰が得点・アウトになったかを勝手に割り当てない。スコアのみの比較用として別に使う。
- 第3アウトの得点タイミング、公式自責点、継投規則、サヨナラの公式記録等が必要な本番処理には、未対応のまま接続しない。

## 統合準備の判断

限定ルール・失敗を明示する検証モードへの接続は可能です。自動で長期リーグを完走させ、全公式成績を確定する本番エンジンへの接続は未完です。稀な未観測経路、原本の複雑な走塁死・交代の復元、公式記録処理を優先して解決してください。

2025年は既知の参考期間です。第8段階で性能を反復調整するなら、適切な新しい未使用期間を別に確保してください。まずは現在の原本の交代・進塁詳細を活用し、追加取得は不足が具体化した項目に限定します。球速・回転・打球角度の実測が必要な物理モデルを始める際は、利用条件を確認した公式戦の計測データが別途必要です。
