# 第12段階への接続仕様

## 利用する境界

- `generation.initial_rosters / newcomers`：既存集団と新規入団者を別生成。固定プロフィール・潜在特徴・現在状態を返します。勝手なロスター補充には使いません。
- `domain.Profile / Talent / State / Injury`：出生情報と現在所属、現在能力と潜在特徴、健康状態を分離。`age_on`は暦日から計算します。
- `world.World.enrol / advance / load / grow / transfer`：入団、暦進行、実記録負荷、年次更新、所属変更の記録。`transfer`は管理用の原始操作で、トレード・契約制度ではありません。
- `adapter.Snapshot / AbilityModel`：真の現在状態を試合前に固定し、既存確率へ接続。無効化時は第10段階へ完全に委譲。潜在才能を試合予測へ直接使いません。
- `integration.prepare_game / apply_game`：日付・出場可能性・全選択ロスター入力の検証、終了試合からの実負荷更新。
- `storage.CareerStore.commit / restore / states_at`：管理者用保存と復元。`commit`で試合・試合前入力・キャリア更新をまとめて確定します。
- `views.export_public / public.PublicAPI`：確定日までの評価・公開状態・完了シーズン成績。真の能力やルート鍵を返しません。
- 既存`stability.Game / HistoryStore / replay_game`：試合の進行と確定履歴の再生。既存の規則・モデル・履歴は第3〜10段階に残します。

## 次に優先すること

検証が十分なら、有限な新人候補生成・獲得・退団によるロスター更新、球団ごとの編成、選手の入れ替わりを接続します。現在は初期60人のまま2シーズンを試験し、引退・故障の穴を無限生成で埋めません。長期に実試合を続けるには、補充の意思決定が必要です。

中途の所属変更はキャリア履歴へ保存できますが、既存シーズン集計は同一シーズン内の球団移動を拒否します。正式な移籍を実装するときは、選手通算と球団別期間成績を分けた新しい集計版を追加し、過去の試合や旧集計を上書きしないでください。

選手の契約・ドラフト順位・年俸・FA・外国人枠・育成枠・登録公示は未実装です。プロフィールの一意IDを制度と切り離し、入団・所属・出場・引退の履歴を参照する構造を維持します。氏名をキーにしません。

## 育成・観測・介入

潜在才能は現在能力の上限予約ではありません。球団の評価情報も真値ではありません。将来のスカウト制度では、評価の誤差、観測時点、観測費用を追加し、内部才能を一般出力へ混ぜないでください。

育成環境係数と出場経験は既に成長へ入ります。現在の環境係数は世界全体の年次入力で、球団別投資制度は未実装です。球団別の育成方針や資金の介入を追加する場合、どの時点の誰の決定かをイベントとして記録し、無関係な選手の乱数をずらさないキー方式を継承します。よい成績を残した選手へ機械的に能力を加算しないでください。

能力・健康パラメータはゲーム上の仮定です。今後、実測で検証できる資料を追加するときは、リーグ差・年齢・選抜・欠測を分けて評価し、MLB2025を未使用テストとして使い直さないでください。係数調整は新しい版・将来試合だけへ適用します。

## 保存・公開

終了したゲーム、試合前入力、成長・故障等の更新後状態は不変です。新しいモデルで昔の能力を再計算しません。再生に確率モデル・成長抽選は不要です。途中の休養投影には凍結した回復規則を使います。

公開APIのホワイトリスト、管理者用DBの分離、研究用と運営用のシード分離を保ちます。実運営に公開Web APIを設ける段階で認証・権限を追加してください。公開研究フィクスチャは再構築可能であり、本番世界の秘密鍵として再利用しません。

20年次の高速検証は20年間のリーグ運営ではありません。実際に実行した複数シーズンの結果と、仮定の年次検証を引き続き別々に報告してください。
