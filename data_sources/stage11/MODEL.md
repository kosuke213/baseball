# 選手モデル・履歴・公開境界の契約

## 能力と成績

内部能力は連続値−3〜3。表示用の中心尺度は `50 + 15×内部値`（0〜100に制限）ですが、一般公開APIは真値をそのまま表示しません。入団時・年次更新時に保存した誤差付き評価を返します。評価の誤差設定は約6.3点で、実測のスカウト精度ではありません。

打席結果の基本確率は第10段階の2023〜2024年MLB由来モデルをそのまま使います。能力アダプターは既存の正の確率へ `exp(補正)` を掛け、正規化します。補正は−1.25〜1.25に制限。確率0の結果へ新しい質量を作らず、走者だけで攻撃が終わる確率も変更しません。進塁・得点・アウト・選手IDの処理は第10段階へ委譲します。途中盗塁を二重抽選しません。

平均能力0・疲労0なら確率は第10段階と完全一致します。アダプター無効化時はモデル版と抽選自体も元モデルへ委譲し、同じ名簿・日付・シードなら試合ID、結果、全ジャーナルが一致します。平均能力の有効化時は新しい入力版を持つため、試合IDやモデル版まで同一とはしません。

| 要素 | 今回の接続 |
|---|---|
| コンタクト | 単打・二塁打・三塁打、三振 |
| 長打 | 本塁打・二塁打・三塁打 |
| 選球眼／三振回避 | 四球／三振 |
| 走力 | 三塁打の確率のみ。盗塁や全進塁への個人補正は未実装 |
| 守備・送球 | 生成・成長・評価保存のみ。試合の守備結果へは未接続 |
| 野手の体力 | 打席・出場負荷による疲労増加 |
| 投手の奪三振・与四球抑制・被本塁打／被安打抑制 | 対応する打席確率 |
| スタミナ・回復・耐性 | 負荷、休養回復、故障確率 |
| 先発・救援適性 | 起用評価。直接の打席確率補正はしない |
| 利き投げ・打ち | プロフィール保存。今回の標準運転では左右補正を新規適用しない |

関連する能力に弱い共通因子を持たせています。長打と三振回避、投手の奪三振と制球に小さな相反因子も加えます。強い実測相関を推定したとはしません。係数・初期分布・相関・成長・健康モデルはすべてゲーム設計上の仮定です。

## 試合前の固定

`integration.prepare_game` は世界の現在日付と試合日を一致させ、出場可能な有限ロスターを選び、真の現在能力・実効能力・疲労・出場状態を不変な `Snapshot` へ固定します。潜在才能は確率アダプターへ渡しません。モデル版に入力の指紋を含め、同じゲームと異なる入力を混ぜません。

試合中はその入力を固定します。試合の途中で疲労による能力低下を再計算する処理は未実装です。実際の打席数、投球アウト数、対戦打者数を使って試合後に負荷を適用し、次の試合の入力へ反映します。球数や球速を捏造しません。守備位置は粗い主位置で、打順出場を守備負荷の代理とします。厳密な守備イニング・DH負荷の分離ではありません。

## プロフィールと現在状態

`Profile`はID、架空名、生年月日、入団日・年齢、利き投打、主位置、役割、国籍、生成版を保持します。現在の所属は`State.team_id`にあり、出生プロフィールへ固定しません。同名でもIDは別です。国籍・氏名フィールドは外国人にも対応できますが、多言語の氏名生成器は実装していません。

初期球団は12、各球団は野手28人・投手32人の60人。NPBの公示・登録区分を参照しつつ、継続試験のための独自人数を選びました。支配下・育成・外国人枠等の正式運用は再現しません。主位置はC/IF/OF/DHとSP/RPの粗い区分で、厳密な守備位置充足は未検証です。

初期ベテランの入団日・故障歴・入団時能力は架空の背景データとして区別します。2026年の世界開始前の試合や成長過程を実行したとはしません。新しく入る選手は`newcomers`で別生成し、入団時能力をその時点の状態として保存します。通算成績は実際に記録した試合・シーズンだけの合計です。

## 潜在才能と年次更新

潜在特徴は成長速度、成熟時期のずれ、衰退への抵抗、変動幅、停滞傾向、能力別の成長傾向です。個人ごとの到達上限や将来成績を予約しません。全員共通の数値上限−3〜3は、モデルの安全な範囲です。

能力ごとに異なる年齢の曲線、個人差、伸びしろ、経験、育成環境、健康、停滞・上振れ・通常変動を使います。成績の打率や本塁打数を入力にして能力を必ず加算する処理はありません。出場による経験は実打席・対戦打者から計上します。育成環境は現在は全体の係数として渡せます。球団別の投資・育成政策の本格制度は後続です。

引退は年齢と現在能力による簡単な確率モデルで、契約・解雇・引退交渉制度ではありません。早熟・晩成・伸び悩み等は、生成した特徴と年次抽選の組合せで生じます。物語のために人数を揃えたり成績を変更したりしません。

## 疲労・健康

疲労は0〜1。出場負荷で増え、暦日による指数回復で減ります。回復率は負荷時点の年齢と回復能力を使います。日付を試合数として加算せず、生年月日から年齢を計算します。

故障確率は負荷・年齢・疲労・既往・個人耐性に依存します。重症度1〜3のゲーム上の状態で、休養→リハビリ→復帰可能（制限）→通常へ進みます。復帰時の影響は復帰が確定するときに抽選します。精密な傷病名・医学予測はありません。休養日数はその故障が起きた時に生成するゲーム用の予定で、入団時に将来の故障日を決めません。

`available / restricted / unavailable / rehabilitating / return_ready / retired` を機械的に判別します。欠場中の選手は起用対象から外します。起用は誤差付き評価と現在の疲労・状態を使う決定的な方針で、先発は最低4日休養し、健康な先発・救援を選びます。足りなければ `RosterShortage` で停止し、選手を勝手に補充しません。

## 乱数と時間

初期生成、スカウト評価、試合、成長、故障、復帰、引退を独立したHMACキーで分けます。選手ID・年／イベント種別・ゲームID等を使い、全員で1本の乱数列を消費しません。ある選手の故障や選手追加が、無関係な選手の成長抽選をずらしません。

同じ初期状態・介入・シード・モデル版なら同じ履歴です。将来のイベント表は作りません。時計を進めたところまでだけ確定します。研究用の固定シードは再現のため公開しています。これは運営用の秘密鍵ではありません。運営世界では新しい非公開のルート鍵を管理し、公開APIに渡さない必要があります。ローカルデモは指定がなければ新しい256bit鍵を作ります。

## 保存・日付時点の再生

`CareerStore`は管理者用SQLiteです。第10段階のゲーム保存スキーマを残し、`careers-history-1`の世界・キャリアイベント・試合前入力・シーズン集計を追加します。各テーブルは更新削除を拒否します。試合、入力、負荷・故障等を同じトランザクションで確定します。過去の試合は確率モデルを使わず再生し、キャリアは保存済み更新後状態とハッシュ連鎖から復元します。

日付指定は確定した世界の日付まで。日付内はイベント順序番号で区別し、公開の「その日」は確定済みの最終状態です。試合前の入力はゲーム別に別保存します。休養の間の日付は、保存された回復率と凍結した第11段階の規則で投影します。新しい成長モデルで昔の能力を再計算しません。世界開始前の未実行期間と未来は拒否します。

## 公開境界

真の能力、入団時能力、潜在才能、成長パラメータ、試合前の内部入力、ルート鍵を持つDBは、管理者用としてローカルに保存します。公開用ZIPやGitHubの公開データへは入れません。一般用の`PublicAPI`はホワイトリストで作ったJSONしか保持せず、内部リポジトリへの参照を持ちません。

公開項目は架空名・年齢・所属・役割等、誤差付き評価と誤差設定、出場状態、一般化した故障情報、完了済みシーズンの成績です。真値や才能を勝手に追加すれば検証で拒否します。シーズン途中の詳細成績API、本格的スカウト、ファン投票、HTTP認証・運営用権限管理は未実装です。ローカルAPIの境界を、本番Webサービスの認証完成とは称しません。

研究用集計には匿名集団の年齢別能力平均等を含めます。個人の真値曲線は内部保存のみ、公開サンプル曲線は誤差付き評価です。再現用研究シードを知ればテスト世界は再構築できます。公開研究用の世界を、秘密が必要な運営世界と同じ鍵で使わないでください。
