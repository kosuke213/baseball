# 第11段階への接続仕様

最新の検証レポートの「主生成モード」「原本限定モード」「858試合」の実測結果を確認してから次段階へ進んでください。生成仮定の採用で安定したことと、原本の全時系列を復元したこと、NPBに校正されたことは別です。

## 引継ぎAPI

- `stability.engine.Game / Team / fictional_team`：打席窓の`step/run`、基本交代、IDとモデル・規則・エンジン・保存版を持つ結果。
- `stability.model.GameModel.load(stage7, stage9_dir, support_path, probability_policy)`：`posterior_support`は生成用事後支持、`mle_baseline`は旧終端推定。`predict_pa/predict_step/sample/support_report`。
- `stability.timeline.Event / Edge / Timeline / constraints / generate`：部分順序と根拠を保持。生成器は未知の秒数を作らず、スコアを見て有利な順序を選ばない。
- `stability.rules.realize / apply_play / adjudicate_events`：生成された順序を適用する処理と、抽選しない得点・アウト裁定。`adjudicate_events`の得点は候補で、第3アウト等で無効にできる。
- `stability.history.GameJournal / replay_rows`、`stability.storage.HistoryStore / replay_game`：確定イベントのみで全成績を再生。新モデルを読み込まない。
- `completion.season.Season`を再利用、`stability.season.run_league`で新版ゲームを実行。重複拒否、null伝播、同じ履歴から同じ順位表・個人成績を作る。
- `fullgame.league.schedule / validate_schedule / Standings`：12球団・各143試合・858試合、順位集計の実験規則。

旧第3〜9段階のAPIと保存物は旧版のまま利用できます。新しい版で過去の試合を黙って再解釈しないでください。

## 選手能力・成長への境界

現在の架空選手は一意IDと所属球団、打者・投手の役割を持ち、全球団・全選手がリーグ平均のフォールバックを使います。個別の潜在能力、年齢、健康・疲労、成長・衰退は今回設定していません。値0を能力なしという架空の実測値にしません。

次段階では外部の版管理された選手状態に、最低限 `player_id / team_id / role / ability_version / latent_ability / pregame_state / effective_date` を保持してください。第10段階にこの能力体系を本格実装したとはしていません。試合前状態の不変な写しと確率アダプターの版を試合リクエストに結び付けてから能力を確率へ接続する必要があります。

確率アダプターは試合前までの情報と、その時点の潜在能力だけを使います。成長・故障の乱数系列は試合系列と分け、将来成績の予約や2027年以降の既知結果の先取りをしません。能力や状態が変わると将来試合の分布だけが変わり、終了試合と公式履歴は変更しません。

## 残るルール・精度の課題

原本だけでは61停止の実際の順序は引き続き不明です。今後の運営では生成仮定をルール・モデル版とともに明示し、変更は将来の試合へ適用してください。時間順序やアウト種別の生成分布は未校正で、全てのトポロジカル順序の一様抽選でもありません。

全公式自責点、セーブ・ホールド、複数救援の裁量、途中カウントの複雑な交代、最低対戦打者やNPB登録運用、第4アウト、全アピール・ランニング本塁打例外、悪天候中断・再開は未完成です。null／要確認を保持し、拡張時は記録対応表を更新してください。

未完了サヨナラの独立ハザード、選手差・球場・守備・戦術による分散、NPBへの校正は別課題です。平均が近いだけで予測精度を認定しません。第10段階の1,000／10,000成功や858試合が成立しても、全合法事象に対する無停止保証とはしません。

安定性が十分なら、以後は極限の物理再現や大規模モデル置換より、選手の能力・成長・衰退・故障と、後続の編成・契約・ファン参加を優先してください。重大な未達が残る場合は、最新レポートの理由を先に処理します。
